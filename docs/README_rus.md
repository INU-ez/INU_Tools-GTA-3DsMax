## ✨ Возможности

- 🧠 **Одно ядро для Blender и Max** — `inu_gta_core` на чистом Python (без `bpy` и `pymxs`): чтение/запись DFF,
  TXD, COL, IFP, IDE, IPL, IMG, `timecyc.dat`, `water.dat`, `map.zon`, `effects.fxp` и линты по правилам движка.
  Обновления ядра синхронизируются между репозиториями.
- 🎨 **Выглядит как Kam's, работает как INU** — нативный роллаут **INU Tools** в командной панели открывает окна
  инструментов из сворачиваемых роллаутов, серых кнопок и зелёных переключателей. Опции и кнопки — те же, что в
  панелях INU для Blender.
- 🎮 **III / VC / SA** — выбор игры переключает версии RW, флаги IDE, таблицы поверхностей и лимиты.
- 📂 **Своё окно выбора файлов** — список файлов как в Max, справа — опции импорта/экспорта INU (как сайдбар
  файлового браузера Blender).
- 🔁 **Горячая перезагрузка** — каждый запуск и каждое нажатие кнопки подхватывают свежий код без перезапуска Max.
- ✂️ **Blender-специфичное намеренно не переносится**: Texture Bake, живые превью, geometry nodes, рисование по
  картам, floater/gizmo.

## 📊 Реализованные функции

| Область | Возможности |
|---|---|
| **DFF / TXD / COL** | Импорт и экспорт моделей, сборка TXD, извлечение текстур, коллизии и свойства материалов |
| **Карты и архивы** | Импорт и экспорт IDE/IPL/IMG, модели из нескольких мешей, связи LOD, общие TXD, отдельный IMG для LOD, обновление библиотек COL |
| **Compiled NODES (SA)** | Редактирование графа, стабильные ID вершин, добавление и удаление точек, перестроение связей, объединение с существующей картой, пересчёт ссылок между 64 районами и проверка перед записью |
| **ID Manager** | Назначение ID, пресеты, поиск конфликтов и защита игровых ID |
| **Машины и персонажи** | Иерархия фреймов, пары `_ok` / `_dam`, масштабирование, зеркалирование, rig и инструменты весов |
| **Анимации** | IFP, ключи анимации, IK педов SA с 13 боксами, перенос FK, Bake & Clear, ограничение стоп плоскостью пола и инструменты камеры; UV-анимация для SA с предупреждениями об ограничениях III/VC |
| **Мир и эффекты** | Вода, зоны, пути, инструменты радара, 2DFX и запись `effects.fxp` |
| **Сцена и освещение** | Проверки и операции над мешами, Prelight / Bake over, параметры COL и отдельные настройки pipeline |
| **Диагностика** | Анализ файлов, проверка ресурсов, восстановление после ошибок извлечения, журналы и профилирование Extract/Import |

**Проверки:** 194 автоматических теста покрывают ядро, файловые операции и адаптеры. IK педа SA также проверен в отдельном процессе Max 2026 на стандартных педах `army`/`bmycr` и `WALK_civi`: все четыре цели конечностей, направления сгиба и боксы локтей/колен, пол, перенос FK, сохранение/открытие сцены и Bake & Clear. Остальные нативные сценарии, Max 2023–2025 и результаты в игре ещё требуют проверки.

**Auto TXD:** при импорте DFF ищет PNG, DDS, TGA, BMP, JPG/JPEG и TIFF по имени текстуры в папке DFF и подпапках. Ближайшие папки имеют приоритет; отдельные картинки используются раньше автоматически извлечённых текстур TXD. Недостающие текстуры загружаются из подходящих TXD. Явно выбранный при том же импорте TXD имеет наивысший приоритет.

**IK педов SA:** выделите скелет и нажмите **Add IK Rig** в IFP IO. Создаются четыре бокса кистей/стоп, четыре бокса локтей/колен, два плеча, спина, голова и корень. **Root motion** выбирает Root вместо Pelvis. Существующая FK-анимация переносится на контролы; скелет без ключей сохраняет оси привязки Max, а весь персонаж поворачивается вертикально. Боксы увеличены и рисуются поверх модели, чтобы их было проще выбрать. Настройки цвета, размера и видимости применяются к боксам. **Add Ground Plane** подключает ограничение стоп, в том числе при добавлении пола после рига. **Bake & Clear IK** записывает вычисленную анимацию на кости GTA и удаляет вспомогательные узлы рига. Для старого рига из четырёх цепочек сначала выполните **Bake & Clear IK**, затем добавьте новый риг. Если предыдущая версия IK исказила стартовую позу, импортируйте исходный DFF заново и добавьте риг: запекание сохранит уже искажённую позу.

Перенос не включает специфичные для Blender Texture Bake, geometry nodes и живые превью. Остались отдельные доработки COL, LOD и адаптеров; подробности и ограничения записаны в [журнале переноса](MAX_TODO_2026-09-28.md).

## 📥 Установка

1. Скачайте и распакуйте репозиторий или склонируйте его в отдельную папку.
2. В 3ds Max откройте **Scripting → Run Script…** и выберите `inu_launcher.ms` из этой папки. Путь определяется автоматически.
3. В роллауте **INU Tools** на вкладке **Utilities** нажмите **Install INU** (или **Update INU** для существующей установки).
4. Дождитесь установки пакета и NumPy, если он отсутствует, затем перезапустите Max. Меню INU Tools, лаунчер и соответствующий нативный плагин подключаются через установленный пакет.

Для обновления замените файлы исходной папки и снова нажмите **Update INU**. Если используете несколько версий Max, запустите установку из каждой версии, которой требуется NumPy. Копировать лаунчер вручную в Startup не требуется.

**Интернет:** при установке требуется доступ к PyPI для скачивания NumPy, если он отсутствует в Python текущего Max. Если отсутствует и `pip`, установщик автоматически скачает временный pip, проверит его контрольную сумму и удалит временные файлы после установки. Если NumPy уже доступен, установка зависимостей не требует интернета; установленные инструменты работают локально.

**Режим разработки:** запустите `run_inu.py` через Python в Max; он открывает окно-лаунчер и перезагружает модули `inu_max` / `inu_gta_core`.

## 🧪 Совместимость

| | |
|---|---|
| 🖥️ **3ds Max** | **2023–2026** (2023–2024: PySide2 / Qt5; 2025–2026: PySide6 / Qt6); нативные проверки ещё не завершены |
| 🎮 **Игра** | GTA San Andreas (основная цель), Vice City и III |
| 💻 **ОС** | Windows x64 |
| 📦 **Зависимости** | Qt из Max и NumPy (лаунчер устанавливает его при отсутствии) |

Установщик регистрирует общий пакет для Max 2023–2026. NumPy хранится отдельно
для каждой версии Python. Если в другом Max NumPy отсутствует, запустите
**Install / Update INU** из его лаунчера.

Нативному `.dli` нужен отдельный SDK соответствующего года. В репозитории есть
отдельные бинарники 2023, 2024, 2025 и 2026 в `plugins/<год>/`. Их версии SDK
и архитектура x64 проверены; нативная проверка внутри Max ещё не завершена. Без них доступны импорт из
окна INU и перетаскивание на окно. Перетаскивание во вьюпорт и операции,
требующие плагина (например, Bake with shadows), недоступны.

Проверки совместимости выполнены на harness; запуск инструментов внутри
каждой версии 3ds Max остаётся отдельной проверкой.

```
  adapter/          сцена Max ↔ структуры ядра (mesh, material, texture, anim, fx, world, zon)
  ops/              модели/карты, NODES, сцена, машины, анимации и мир

dev/tests/         регрессионные тесты и скрипты проверок внутри Max
```

</details>

<details>
<summary>🔧 Правки ядра</summary>

`inu_gta_core/` — копия папки `core/` из Blender-репозитория. Ядро правится **там** и копируется сюда целиком
(`core/` → `inu_gta_core/`), чтобы обе версии были синхронны. Ядро не должно импортировать `bpy` или `pymxs`.
